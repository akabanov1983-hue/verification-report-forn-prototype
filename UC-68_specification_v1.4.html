Назначение документа

Определить один итоговый комплект для результата проверки онлайн-продукта и формировать отчеты по сохраненному результату. Настройка комплектов, включая импорт и экспорт, описана в UC-89.

Термины

ТерминОпределение
Верификация документовПроверка наличия настроенных документов, их размещения, применимых дат и обязательных связей досье.
Комплект документовПеречень видов и подвидов документов для одного способа оформления продукта. В интерфейсе называется "Комплект N". Сохраненный комплект содержит хотя бы одну заполненную строку.
Автоматический отчетОтчет, формируемый по завершении автоматической верификации, запущенной по запросу УОС.
Полный отчетОтчет, формируемый по запросу пользователя за заданный период в одном из двух режимов: все верифицированные документы или только документы с расхождениями.
РасхождениеОтсутствие ожидаемого объекта или документа, неверное место размещения документа либо иная ситуация, препятствующая завершению верификации.
Причина расхожденияТекстовое описание расхождения.
Исторический срез расхожденийСохраненные расхождения, выявленные внутри отчетного периода не позднее даты состояния. Дата устранения показывается только для событий не позднее даты состояния. Устраненные до даты состояния расхождения сохраняются в срезе с датой устранения.
Дата состоянияДата внутри отчетного периода, по которой отбираются сохраненные факты выявления и устранения. События с датой после даты состояния не учитываются.
Дата выявления расхожденияДата, в которую ПК ГЭДК зафиксировал расхождение по результатам верификации.
Дата устранения расхожденияДата события, устранившего соответствующее расхождение: размещения недостающего документа, исправления его размещения либо исправления связи досье. При историческом срезе значение отображается только для события не позднее даты состояния.
БПКБанковская платежная карточка.
УОСУчетно-операционная система, передающая в ПК ГЭДК сведения об онлайн-продуктах и периоде автоматической верификации.
ПК ГЭДК/ГЭДК/Система храненияПрограммный комплекс "Гибридное электронное досье клиента". В настоящих спецификациях используется наименование ГЭДК.
Календарная датаДата календарного дня, определенная без корректировки по бизнес-правилам обработки конкретного онлайн-продукта.
Бизнес-датаДата, определенная УОС по бизнес-правилам обработки конкретного онлайн-продукта. Может отличаться от календарной даты - не включать выходные и праздничные дни.
Ответственный сотрудникСотрудник, который на момент формирования рассылки указан в справочнике ответственных сотрудников по онлайн-продуктам. Актуальность записи и закрепления сотрудника обеспечивает уполномоченное бизнес-подразделение
Итоговый комплект документов (далее - Итоговый комплект)Один комплект, по которому сохранен результат конкретной проверки онлайн-продукта. Он может быть верифицированным либо иметь ошибки.
Верифицированный комплектКомплект, для которого найдены все настроенные документы и выполнены применимые проверки размещения, дат и обязательных связей досье.
Дубликаты настройкиПолностью одинаковые комплекты в старой настройке. При полном совпадении всех проверяемых полей используется первый по номеру. Это правило не разрешает повторять подвид при создании или импорте настройки.
Нарушение использования одного комплектаДля одного оформления найдены документы разных комплектов. Это нарушение, даже если один или несколько комплектов заполнены полностью.

Бизнес-правила идентификации комплекта

КодПравилоОписание
BR-008Уникальность подвида документаПодвид документа можно указать только один раз в настройке онлайн-продукта. В другом онлайн-продукте этот подвид использовать можно.
BR-010Один комплект при оформленииПри одном оформлении онлайн-продукта используется только один комплект. Все документы этого оформления, указанные в настройке продукта, должны относиться к нему.
BR-011Определение комплекта

ГЭДК определяет комплект по подвиду найденного документа. Учитываются только документы текущего оформления продукта. Их подвиды должны быть указаны в настройке этого продукта. Правила поиска документов не меняются.

Почему это важно. Уникальный подвид позволяет определить комплект по найденному документу. При одном оформлении продукта используется один комплект. Если эти правила не соблюдаются, документы могут указывать на разные комплекты. Тогда потребуется отдельный алгоритм выбора. Поиск и проверка документов станут сложнее.

Правило выбора итогового комплекта

СитуацияПоведение
Найдены документы одного комплекта и все применимые проверки выполненыИтоговым является этот комплект. Продукт может быть признан успешно верифицированным только после проверки, что для того же оформления не найдены документы других комплектов.
В настройке один непустой комплектИтоговым является этот комплект. Сохраняются все выявленные в нем ошибки.
Документы найдены только в одном комплекте, в том числе частичноИтоговым является комплект, к которому относятся найденные подвиды документов. Проверяются все его обязательные документы. Номер комплекта и количество найденных документов не влияют на выбор.
Документы не найдены ни в одном непустом комплектеПредварительное правило: итоговым является первый непустой комплект по текущему номеру. Пустые комплекты пропускаются.
Для одного оформления найдены документы разных комплектов
  • ГЭДК фиксирует нарушение правила использования одного комплекта.
  • Итоговый комплект автоматически не выбирается по номеру, количеству или доле найденных документов.
  • Формат результата, строки отчета и уведомление согласуются с заказчиком.
Ошибка настройки продуктаПродукт не имеет заполненных комплектов. Проверка его документов не выполняется. Успешный результат не присваивается.

Целевой процесс

ШагИсполнительДействиеРезультат
1ГЭДКПолучить состав и текущий порядок настроек на момент запуска.Изменения после запуска не подменяют состав этого результата.
2ГЭДКПроверить заполнение настройки. Выявить пустые комплекты и обработать полные дубли старой настройки.Пустая настройка означает ошибку. Порядок продолжения запроса согласуется по B-07.
3ГЭДКНайти документы текущего оформления продукта по действующим правилам. Определить комплект каждого документа по его подвиду.Если подвиды не повторяются, документ относится к одному комплекту. Документы разных комплектов означают нарушение правила.
4ГЭДКПри наличии документов одного комплекта определить этот комплект итоговым и проверить все его обязательные документы.
  • Проверены наличие, размещение, применимые даты и обязательные связи.
  • При полном отсутствии документов применяется отдельное предварительное правило.
  • Для нарушения использования одного комплекта представление результата требует согласования.
5ГЭДКДля определенного итогового комплекта сохранить строки результата его проверки.Ошибки отсутствующих документов других альтернатив не добавляются. Нарушение использования одного комплекта не подменяется результатом произвольно выбранной альтернативы.
6ГЭДКДля определенных итоговых комплектов сформировать автоматический отчет и выполнить рассылку.В файле ошибки итоговых комплектов продуктов получателя. Отражение нарушения использования одного комплекта и уведомление по нему требуют отдельного согласования.
7ГЭДКПри получении события исправления дополнить историю устранения.Исходный факт выявления сохраняется. Закрытие за счет альтернативы - предлагаемое правило B-03.
8ГЭДКПо запросу пользователя выгрузить сохраненные результаты.Новая проверка и выбор по текущей настройке не выполняются.

FR-COM-009ПК ГЭДК должен проверять наличие всех документов, указанных в списке проверяемого комплекта.Отсутствие одного настроенного документа не дает верифицированного комплекта.

FR-COM-004ГЭДК должен включать в результат все выявленные ошибки итогового комплекта, включая отсутствие, размещение и связь досье.Ошибка размещения А и отсутствие Б одного итогового комплекта обе присутствуют в его результате.
FR-COM-011ПК ГЭДК не должен включать в результат проверки ошибки остальных комплектов.При верифицированном Комплекте 2 ошибки Комплекта 1 в новом результате отсутствуют.

Проверка и выбор комплектов

КодТребованиеКритерий приемки
FR-KIT-001ГЭДК должен использовать состав и порядок комплектов, действующие на момент запуска верификации.Изменить настройки после запуска. Старый отчет остается основанным на сохраненном результате, следующий запуск использует новые настройки.
FR-KIT-002ГЭДК должен искать документы каждого заполненного комплекта отдельно. Поиск выполняется по текущим номерам комплектов. Документы разных комплектов не объединяются.После удаления комплекта следующий запуск использует текущие номера. Поиск по настройкам разных комплектов не объединяет их документы в один комплект.
FR-KIT-003ГЭДК должен считать комплект верифицированным, если найдены все настроенные документы и выполнены применимые проверки размещения, дат и обязательных связей досье.Все документы найдены, но применимая проверка даты, размещения или связи выявила ошибку: комплект не является верифицированным.
FR-KIT-004Если все найденные настроенные документы проверяемого оформления продукта принадлежат одному комплекту и этот комплект верифицирован, ГЭДК должен определить его итоговым независимо от номера.Найдены все документы Комплекта 2, все применимые проверки выполнены, документов других комплектов нет: итоговый комплект - Комплект 2.
FR-KIT-005Если все проверяемые поля нескольких комплектов полностью совпадают, ГЭДК должен проверять только первый по номеру. Это исключение для старых данных. При создании и импорте настройки повторы подвидов запрещены.Полный дубль дает результат первого комплекта. Комплект пропускается только при полном совпадении всех полей. Одного совпавшего подвида недостаточно.
FR-KIT-006Если ГЭДК обнаружил пустой комплект, он должен зафиксировать ошибку настройки. Пустой комплект нельзя считать проверенным.У продукта есть пустой комплект. Он не дает успешного результата проверки. Порядок обработки остальных продуктов уточняется в B-07.
FR-KIT-007ГЭДК не должен проверять документы продукта без заполненных комплектов.Проверка документов не выполнена из-за настройки. Продукт не отмечен успешно проверенным.
FR-KIT-008Если найденные документы одного оформления относятся к одному комплекту, ГЭДК должен выбрать этот комплект итоговым. Номер и полнота комплекта не влияют на выбор.Найден только В из Комплекта 2 (В + Г): итоговый комплект - Комплект 2, проверяется наличие Г и применимые проверки В.
FR-KIT-009Если непустой комплект только один, ГЭДК должен определить его итоговым и при отсутствии всех его документов.Единственный комплект А + Б при отсутствии А и Б дает его ошибки, а не неопределенный выбор альтернативы.
FR-KIT-010ГЭДК не должен добавлять в автоматический и полный отчеты колонку "Номер комплекта". Остальные изменения состава колонок, описанные в требованиях к отчету, сохраняются.Колонки причин и дат расхождения присутствуют; колонка "Номер комплекта" отсутствует.
FR-KIT-011Для формирования полного отчета ГЭДК должен использовать сохраненные результаты из базы данных без запуска процесса проверки документов или выбора комплекта по текущей настройке.
  • Запросить полный отчет: файл содержит сохраненные результаты, новый запуск верификации и новый результат проверки не создаются.
  • После изменения настройки повторная выгрузка старого результата не заменяет его состав новой настройкой.
FR-KIT-012Для продукта без заполненных комплектов ГЭДК не должен создавать строки отсутствующих документов в отчете.Отсутствие настройки не превращается в список отсутствующих документов. Представление ошибки настройки согласуется по B-08.
FR-KIT-013Изменение состава или порядка комплектов не должно автоматически пересчитывать ранее сохраненный результат верификации.После перенумерации выгрузка старого результата содержит прежний сохраненный состав.

Вопросы на уточнение

КодКомуВопросПримеры или варианты
B-01БизнесСогласовать использование одного комплекта при оформлении продукта. Комплект определяется по уникальному подвиду документа.
  • При одном оформлении продукта используется один комплект. Все документы этого оформления, указанные в настройке продукта, относятся к нему.
  • Подвид документа можно указать в настройке продукта только один раз. ГЭДК определяет комплект по подвиду найденного документа.
  • Документы других оформлений не учитываются.
  • Документы разных комплектов означают нарушение правила. Выбор по номеру или количеству найденных документов не выполняется.
  • Просим подтвердить правило. Также нужно согласовать сообщение об ошибке, строки отчета, уведомление и порядок исправления.
  • Без этих правил потребуется отдельный алгоритм выбора комплекта. Поиск и проверка документов станут сложнее.
B-02БизнесПодтвердить вывод только первого непустого комплекта при отсутствии всех документов либо согласовать показ всех альтернатив.
  • CB: Комплект 1 - ind_doc_5, подвиды 1 и 2.
  • Комплект 2 - ind_doc_51, подвиды 1 и 2.
  • Комплект 3 - ind_doc_51, подвиды 3 и 4.
  • Вариант 1: показать отсутствие документов Комплекта 1.
  • Вариант 2: показать все три допустимых способа оформления как альтернативы.
B-03БизнесСогласовать закрытие прежних ошибок за счет альтернативного комплекта с правилом одного комплекта при оформлении.
  • Сначала документов не было. В результате выбран Комплект 1. Позже найден и проверен только Комплект 2. Нужно подтвердить закрытие прежних ошибок Комплекта 1.
  • Если остаются документы обоих комплектов, правило одного комплекта нарушено. Закрытие прежних ошибок для этого случая не согласовано.
  • Нужно подтвердить возможность смены способа оформления. Также требуется определить порядок учета прежних документов.
  • Предлагаемая дата закрытия - дата события, после которого выбранный комплект прошел все проверки.
B-05Бизнес и вендорУточнить отбор периода для режима "Все верифицированные документы" и источник даты сортировки.
  • Для расхождений используется дата их выявления.
  • Для строк без расхождений основание включения в период не установлено.
  • FR-COM-006 сортирует по созданию заявки, а колонка отчета содержит дату создания документа.
B-06Бизнес и вендорСогласовать заполнение строк ошибок досье и связи и дополнить каталог недостающих причин.
  • В таких строках может отсутствовать идентификатор документа.
  • Уточнить ID, номер документа и значение "Наличие документа в комплекте".
  • Нужны причины для несовпадения contractDate и contract_date и ошибок по продуктам, не связанным с БПК.
V-01ВендорКак сохраняется результат при ошибке настройки продукта?
  • Вендор подтвердил HTTP 200, сохранение запроса и отправку пустого отчета в текущей версии.
  • Состав отдельного результата проверки в БД не указан.
  • Нужно уточнить хранение ошибки настройки и ее связь с запросом.
V-04ВендорКак связывать события исправления с сохраненными результатами проверки?
  • Как событие документа или связи связывается с конкретным открытым расхождением.
  • Как исключается повторное закрытие при повторной доставке события.
  • Как обрабатываются несколько результатов проверки одного продукта.
  • Какие события и поля журналируются при запуске, завершении и технической ошибке.
  • Как сохраняется исторический срез при получении запоздалого события с более ранней датой.
V-05ВендорКак обрабатывать старую настройку, если один подвид повторяется в разных неполностью одинаковых комплектах?
  • При создании и импорте настройки повтор подвида в одном продукте запрещен.
  • При проверке полностью одинаковых старых комплектов используется только первый комплект.
  • Поведение для старых комплектов с частичным совпадением подвидов нужно уточнить.
V-06ВендорУточнить правила дат и исключения расширенной проверки.
  • Формат, часовой пояс и границы startDate и endDate.
  • Сравнение contractDate с contract_date и обработка отсутствующих или недопустимых значений.
  • Проверка номера счета при единственной ссылке и пустом номере связанного счета.
  • Как определяется досье БПК при нескольких найденных досье.
B-07БизнесКак обрабатывать запрос, если один продукт не имеет допустимой настройки?
  • Остановить весь запуск.
  • Не проверять этот продукт, но проверить остальные.

  • Как показать ошибку, если проверены другие продукты.
